# Переработка TrafficSignalStudio на базе механики Eclipse SUMO

Проект использует SUMO как вычислительное ядро, а TrafficSignalStudio — как собственный интерфейс и рабочее место инженера. Модели отдельных автомобилей, маршрутов, полос, очередей, потерь времени, светофорных контроллеров и сетевой динамики рассчитывает SUMO; приложение готовит входные данные и анализирует результаты.

## Уже предусмотрено в ядре
- Конвертация OSM XML/PBF в транспортную сеть SUMO через `netconvert`.
- Генерация маршрутов и поездок через штатный `randomTrips.py`.
- Запуск `sumo` или `sumo-gui` с фиксированным seed.
- Извлечение числа завершённых поездок, средней длительности, ожидания и потери времени из XML-отчётов.
- Чтение идентификаторов светофорных программ, числа фаз, длительности цикла и строк сигналов из `.net.xml`.

SUMO устанавливается отдельно; его исполняемые файлы не копируются в проект. OSM данные необходимо сопровождать атрибуцией OpenStreetMap. Данные 2ГИС Places API не считаются готовой дорожной сетью.

## Инженерные ограничения
Автоматическое сопоставление редактора фаз с контролируемыми связями SUMO требует явного назначения каждой полосы/поворота на сигнальную группу. Приложение не должно автоматически придумывать строки `state` для реального перекрёстка. Перед использованием результата для реального проекта нужны проверка геометрии сети, сигналов, потоков и калибровка по наблюдениям.
